PyAutoGUI laptop automation architecture

Ubiquitous language, runtime behavior, and implementation model for the laptop control CLI.

Ubiquitous language

This table defines the domain terms used across the tool, automation plans, and agent interactions.

Term Definition
Logical point Application coordinate unit used by macOS WindowServer and PyAutoGUI (for example, 1440x900).
Physical pixel Raw hardware display framebuffer raster pixel used in screenshots (for example, 2880x1800).
Retina scale factor Ratio of physical pixels to logical points (2.0 on standard MacBook displays).
Atomic action Single input primitive sent to the operating system (click, move, type, press, scroll).
Batch plan Ordered sequence of actions encoded in JSON with delays and target coordinates.
Template patch Small cropped image representing a UI element used for 2D cross-correlation matching.
Target bounding box Rectangular screen bounds defined by minimum and maximum x and y coordinates.
Failsafe trigger Emergency abort mechanism invoked by slamming the mouse cursor into coordinate (0, 0).

System behaviour

1. Input control mechanism

PyAutoGUI generates input events through macOS CoreGraphics and Quartz event taps. When Antigravity has Accessibility permission, the process obtains an authorized Mach port connection to the WindowServer daemon.

flowchart LR CLI[laptop-control CLI] --> PyAutoGUI[PyAutoGUI Layer] PyAutoGUI --> PyObjC[PyObjC Quartz Framework] PyObjC --> CG[CGEventCreate / CGEventPost] CG --> WS[macOS WindowServer] WS --> Target[Active Window / Steam] 
// macOS C-level Quartz call executed under PyObjC
CGEventRef moveEvent = CGEventCreateMouseEvent(
    NULL, kCGEventMouseMoved, CGPointMake(x, y), kCGMouseButtonLeft
);
CGEventPost(kCGHIDEventTap, moveEvent);
CFRelease(moveEvent);

2. Establishing UI element coordinates

The screen presents two coordinate spaces. Screenshots from screencapture or CoreGraphics are 2880x1800 pixels. PyAutoGUI accepts logical coordinates in 1440x900 points. The tool queries display scaling and maps every coordinate automatically.

flowchart TD Raw[Physical Framebuffer: 2880x1800] --> Scaler[Retina Scale Factor: 2.0x] Scaler --> Logical[Logical Screen: 1440x900] Template[Template Matching: cv2.matchTemplate] --> Bounding[Physical Bounding Box: 769, 900 to 1096, 968] Bounding --> Convert[Scale Translation: divide by 2.0] Convert --> TargetPt[Target Click Coordinate: x=466, y=467] 
def to_logical_coords(x: float, y: float, is_physical: bool, scale: float) -> tuple[float, float]:
    if is_physical and scale > 0:
        return x / scale, y / scale
    return x, y

3. Presenting screen information to agents

Screen state is communicated to the agent via three distinct representations:

  • Visual image buffer: Screen grabs stored as PNG files and inspected directly by the agent model.
  • Window geometry metadata: Quartz window lists queried via CoreGraphics containing application names and bounding boxes.
  • Structured CLI JSON output: Machine-readable JSON strings returned on standard output containing match confidences and coordinates.
{
  "found": true,
  "confidence": 0.9984,
  "threshold": 0.8,
  "box": { "x": 384.5, "y": 450.0, "width": 164.0, "height": 34.0 },
  "center": { "x": 466.5, "y": 467.0 },
  "scale_factor": 2.0
}

4. Behavior when targets are not found

When a target element cannot be matched above the requested confidence threshold (default 0.80), the tool exits with code 1 and outputs the highest observed correlation score without moving the mouse. In batch mode with --stop-on-error, execution halts immediately to prevent misclicks on unintended controls.

flowchart TD Scan[Run cv2.matchTemplate across scales] --> Check{Confidence >= Threshold?} Check -- Yes --> Action[Return Coordinates and Execute Click] Check -- No --> Fail[Output Failure JSON and Exit Code 1] Fail --> Stop[Halt Batch Pipeline]

5. Command corpus and discovery

The command suite is housed in tools/pyautogui-cli/laptop_control.py with a companion executable wrapper in bin/laptop-control. Agents discover supported commands using self-documenting introspection:

  • Standard help: laptop-control --help lists all subcommands and parameters.
  • Subcommand help: laptop-control <command> --help describes options for a specific command.
  • Self-test diagnostics: laptop-control self-test verifies coordinate scaling, key mappings, and OpenCV operations.
  • Test suite: python3 -m unittest tools/pyautogui-cli/tests/test_laptop_control.py runs end-to-end command tests.

6. Deriving intent into action

When given a high-level goal, such as opening an application and navigating to a setting, the agent follows a seven-stage decomposition sequence.

Implementation details

Domain model

The domain model separates screen coordinates, device inputs, visual recognition, and plan sequences into clear abstractions.

Data model

Batch plans use a flat JSON schema. Each step specifies an action, target properties, and optional delays.

]

Error handling

Errors are caught at four distinct boundaries:

  • Display query failures: If CoreGraphics mode cannot be read, the tool falls back to AppKit NSScreen, then to PyAutoGUI screen size.
  • Failsafe exception: Dragging the cursor to any screen corner immediately raises an uncatchable abort signal, preventing endless click loops.
  • CLI argument validation: Missing templates, unknown keys, and malformed JSON fail fast before any hardware events are posted.
  • POSIX return codes: Success exits with 0. Missing targets or invalid commands exit with 1. System exceptions exit with non-zero codes.

Bottlenecks

The primary latency sources are:

  • Subshell startup: Running via uv run incurs 100-300ms python startup latency per command invocation. Batch mode mitigates this by running the entire sequence inside a single process invocation.
  • Screen capture roundtrips: Taking full 2880x1800 screenshot dumps to disk takes 120-200ms per capture.
  • Convolution cost: Multi-scale template matching on 5-megapixel images takes 150-300ms per template.
  • Application rendering: Steam and games require 500-1500ms to repaint UI views after receiving clicks.

Tradeoffs made

The architecture adopted three explicit technical tradeoffs:

  • PEP 723 inline script versus installed package: Selected standalone script execution with inline dependency metadata so no virtualenv activation or installation step is required.
  • Visual coordinate matching versus Accessibility DOM trees: Selected visual coordinates and templates because custom-rendered interfaces (Steam WebViews, games, Electron canvases) often omit macOS accessibility attributes.
  • Stateless batch CLI versus resident daemon: Selected simple batch execution scripts over an active background daemon, prioritizing simplicity and zero idle resource usage.

Limitations

  • Display sleep: macOS disables Quartz event taps when the screen locks or display sleeps.
  • Window movement: Absolute coordinates fail if target windows are dragged to a different position without re-anchoring.
  • Multi-display offsets: Coordinates currently assume the primary display space at origin (0, 0).
  • Hardware overlays: Certain full-screen 3D games render directly via Metal bypassing WindowServer compositing.
