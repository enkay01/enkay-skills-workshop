# Mac computer use baseline, 26 September 2026

## Task and conditions

From the Steam Store, open Library Home, search for `Football Manager 26`, select the game, and click Play. The endpoint was Steam showing `Launching` and `Synchronizing cloud`, not the game's own window. Steam was already running and had previously selected the game in the Library. This was one timed, vision-guided run of the existing global `mac-computer-use` skill.

An earlier setup attempt was excluded: Steam was already on the game page, and focus moved to System Settings before a reset click. The timed run began after the Store was visibly open. The agent then opened Library Home to leave the previously selected game page.

## Timings

| Measure | Time |
| --- | ---: |
| End-to-end wall clock, first action to verified `Launching` state | 148.7 s |
| Nine CLI invocations, including six screenshot captures, Steam focus, clicks, and typing | 34.2 s |
| Image loading calls | 0.8 s |
| Remaining wall time, including agent reasoning, planning, tool setup, and communication | 113.7 s |

Individual command timings were 3.38 s to focus Steam, 2.10 s to click Library, 2.52 s for a screenshot, 1.52 s to open Library Home, 3.03 s for a screenshot, 5.00 s for a search batch, 6.67 s for search recovery, 4.48 s to select the result, and 4.64 s to click Play. These command times sum to 33.34 s; invocation overhead outside the child process accounts for the remainder of the 34.2 s figure.

The first search batch used the tool's clipboard paste option. Steam received only `v`, so the agent removed it and typed `Football Manager 26` as keystrokes in a recovery batch. The failure and recovery are included in the wall time. The run used batch execution for predictable actions and inspected the resulting screenshots between navigation decisions.

After the run, five read-only `size` calls took 0.94, 0.49, 0.49, 0.49, and 0.50 s of child-process wall time. These are lower than the warm startup measurements from the previous day, so startup cost varies with the host's current cache and load.

## Interpretation and next comparison

This is one observation, not a latency distribution. The 113.7 s residual is not a pure model inference measurement; it includes all time outside the measured calls. A comparison run should use the same Store starting screen and the same `Launching` endpoint, record full wall time and per-stage timing, and report completion failures separately. All temporary screenshots and batch plans from this run were stored in one owned directory for deletion after the report was saved.
